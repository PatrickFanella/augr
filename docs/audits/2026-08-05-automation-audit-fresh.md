### 2026-08-10 provider resilience implementation

The August 10 failure diagnosis identified three additional provider/data reliability issues during fresh post-deploy observation: Polygon clients did not share a credential-level quota, the stock OHLCV provider chain could mask mixed empty/error responses as successful empty data, and the premarket gap scanner retried every Polygon snapshot batch after deterministic entitlement/quota failures.

Local remediation now adds a shared strict Polygon runtime limiter, wires the stock provider registry plus options, universe, automation, and fallback Polygon clients through that same limiter, and keeps the Polygon constructor backward-compatible for tests. Historical OHLCV stats now include `ProviderFailures` and can return partial stats with a joined provider error, allowing `current_data_refresh` to persist a truthful summary while still failing closed. The OHLCV provider chain now ignores unsupported-provider capability misses, but returns `ErrProviderCoverageIncomplete` when one provider returns empty data and another real provider fails. The gap scanner now stops after the first 401/403/429 snapshot failure and records that as a clear Polygon access/quota blocker instead of spending all batches on an already deterministic failure.

Focused regression coverage was added for mixed empty/error OHLCV chains, per-symbol historical provider-failure stats, gap-scanner provider-access classification, and strict Polygon pacing. Verification on the local remediation set: `go test ./internal/data ./internal/data/polygon ./internal/automation ./cmd/tradingagent` passed, then full `go test ./...` passed on August 10. These code tests do not close the production evidence rows; `current_data_refresh`, `gap_scanner`, `ticker_discovery`, and downstream market scans still require fresh post-deployment runs.
